# cskwb01 项目 Profile

## 定位

`cskwb01` 用来保存此前已经沉淀并验证过的 Polaris Cucumber/BDD 能力。这个项目是历史三端日志口架构，不要被当前 `venusws63` 的无 CP 拓扑覆盖。

## 硬件拓扑

| 角色 | 串口 | 波特率 | 用途 |
| --- | --- | --- | --- |
| AP / cskap | `COM13` | `921600` | AP 日志、部分 AP 侧控制 |
| CP / cskcp | `COM14` | `921600` | CP 唤醒、命令关键词、底层链路证据 |
| WB01 / ASR | `COM11` | `921600` | ASR/WB01 日志、在线唤醒/识别证据 |
| control | `COM12` | `115200` | 上下电、复位、PA/声卡链路控制 |

> 2026-06-01 当前接线已更新为上述映射；历史 run 中的 COM14/COM12/COM13/COM15 仅作为旧证据读取。

## PA/声卡链路前置

如果出现“声卡播放命令返回 0，但 CP/AP/ASR 都没有唤醒证据”，先不要直接判固件唤醒失败，优先按播放/PA/设备听音链路排查。

在控制串口执行：

```text
uut-pa.on
pa-enable.set 0 17 0 1
```

断言和归因规则：

- 这两个命令必须发到 `control` 串口，不能发到 AP/CP/ASR 日志口。
- 执行后应复播 `小美小美`；若出现 CP `WAKE(1)`、AP `wakeup_callback`、ASR/WB01 wake marker，则归因为 PA/声卡链路前置缺失，而不是固件唤醒失败。
- 如果 PA 前置已执行、声卡 key 正确、播放返回 0，仍没有任何唤醒证据，再进入设备听音链路/麦克风/固件唤醒问题排查。

## 断言口径

- 唤醒闭环：CP `WAKE(1)` + AP `wakeup_callback` + WB01/ASR `online_wakeup` 或 wake marker。
- 命令闭环：CP `WAKE(0)` / 命令关键词 + AP/WB01 `offline_asr_callbak` / `online_asr_callbak` + TTS/状态响应。
- 失败归因：声卡播放失败、串口缺失、CP 缺失、AP 缺失、ASR 缺失、需求 oracle 不清楚分别归因。

## 已保存能力

以下是此前 Cucumber 框架已经沉淀的可执行能力基线，环境满足时按 `cskwb01` 口径执行：

- 首次唤醒、识别模式下唤醒、唤醒响应时间、连续唤醒、随机间隔唤醒、唤醒率压测。
- 半双工识别、全双工识别、离线/在线 one-shot 间隔矩阵。
- 基础命令词识别、需求命令词小样本、需求自由说探索性小样本。
- 打断前置自播测量、自播中唤醒打断、自播中识别打断。
- 静默误唤醒、人声干扰误唤醒、白噪声误唤醒。
- 在线 VAD 专项、归因一致性复核。
- 联网恢复基础验证：仅当设备连接本机可控 Wi-Fi/热点时执行。

## 不自动覆盖的内容

- `venusws63` 无 CP，不代表 `cskwb01` 的 CP 断言无效。
- WB01 云控当前不作为 WS63 上线验证阻塞项；若 WB01 云控业务码异常，按 BLOCKED 留证，不改写为固件 FAIL。
- 如果新项目波特率、串口或 PA 前置不同，应新建项目 profile，不要直接改这个基线。
